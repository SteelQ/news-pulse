# 项目开发进度与任务追踪

本文档用于追踪 News Pulse 项目的开发进度、任务状态和里程碑。

## 任务状态说明

- **待开始 (Todo)**：任务已规划，尚未开始
- **进行中 (In Progress)**：任务正在开发中
- **代码审查 (Review)**：代码已完成，等待审查
- **测试中 (Testing)**：代码审查通过，正在测试
- **已完成 (Done)**：任务已完成并合并
- **已暂停 (Blocked)**：任务因依赖或问题暂时暂停
- **已取消 (Cancelled)**：任务已取消，不再进行

## 任务模板

每个任务应包含以下信息：

```markdown
### [TASK-XXX] 任务标题

- **状态**: 待开始 | 进行中 | 代码审查 | 测试中 | 已完成 | 已暂停 | 已取消
- **负责人**: @username
- **优先级**: 高 | 中 | 低
- **开始日期**: YYYY-MM-DD
- **预计完成日期**: YYYY-MM-DD
- **实际完成日期**: YYYY-MM-DD（如已完成）
- **关联 PR**: #PR_NUMBER（如有）
- **阻塞项**: 描述阻塞原因（如有）
- **验收标准**:
  - [ ] 标准 1
  - [ ] 标准 2
- **备注**: 其他需要说明的信息
```

## V1 里程碑（规划）

> 说明：V1 目标是“采集 → 存储 → 展示”的最小闭环，先以 RSS/Atom 为主，后续再扩展复杂抓取与账号体系。

### M0：环境可跑通（开发闭环）

- **验收标准**:
  - [ ] `docker compose up -d` 可启动全部服务且健康检查通过（db）
  - [ ] 后端可访问（`/` 或 `/api` 有明确响应）
  - [ ] 前端开发服务器可访问（Vite 热更新可用）

### M1：数据模型与后端 API 可用（数据闭环）

- **验收标准**:
  - [ ] 数据库有“来源（Source）/内容条目（Entry）/采集运行记录（FetchRun）”等最小表结构
  - [ ] 提供可供前端消费的列表/详情 API（分页、基础筛选）

### M2：采集器可执行（采集闭环）

- **验收标准**:
  - [ ] 可对单个 Source 执行采集命令并落库
  - [ ] 具备去重策略与失败记录（可追溯）

### M3：前端展示可用（展示闭环）

- **验收标准**:
  - [ ] 可浏览聚合列表（分页/筛选/搜索至少其一）
  - [ ] 可查看条目详情并跳转原文

### M4：联调与发布准备（可交付）

- **验收标准**:
  - [ ] 前后端联调通过（前端默认指向后端 API）
  - [ ] 最小部署方案明确（Nginx 反代 /api + 前端产物托管）

## 使用说明

### 更新频率

- **开发阶段**：每次任务状态变更时更新
- **每日更新**：每日结束时更新任务状态和进度
- **PR 提交**：提交 PR 时更新任务状态为"代码审查"并关联 PR 号
- **合并完成**：PR 合并后更新任务状态为"已完成"

### 更新规范

1. 新增任务时，按照任务模板填写完整信息
2. 任务状态变更时，更新状态字段并在变更日志中记录
3. 任务完成后，填写实际完成日期并标记验收标准
4. 阻塞任务应明确说明阻塞原因和预期解决时间

### 优先级说明

- **高**：关键功能，影响核心业务或发布时间
- **中**：重要功能，不影响核心流程
- **低**：优化或非紧急功能
